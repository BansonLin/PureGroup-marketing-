# 整合協議（Integration Protocol）v1

本文件規範外部 AI 報告（ChatGPT／Gemini／Claude.ai）如何被回收、分級、驗證並整合進 V2 報告。目的：讓整合可重複、可稽核，且不依賴任何一個人的記憶。

## 1. 回收（Intake）

| 步驟 | 動作 | 負責 |
|---|---|---|
| 1 | 報告存入 `03-inbox/<ai>/`，檔名與中繼資料依 `03-inbox/README.md` | Banson |
| 2 | Claude 建立回收登記表 `03-inbox/_intake-log.md`：檔名、AI、模式、範圍、日期、字數、來源數、在地語言來源數 | Claude |
| 3 | 格式檢查：是否有 8 章骨架、12 市場比較表、附錄關鍵指標表；缺項記錄但不退件 | Claude |

## 2. 來源分級（每份報告、每條來源）

| 等級 | 定義 | 整合用法 |
|---|---|---|
| A | 政府統計、法規原文、央行、普查、上市公司年報／招股書 | 直接採用，標【實際】 |
| B | 產業公會、顧問公司公開報告、研究機構（矢野、KCERI、CBDA、艾瑞等）、主流財經媒體引用的原始數據 | 採用，標【實際】＋機構年份 |
| C | 市調公司新聞稿、平台自報數據、未附方法論的估計 | 只作區間；單獨出現標【示意】 |
| D | 部落格、AI 未附 URL 的數字、無法開啟的 URL | 不採用 |

## 3. URL 逐條驗證

- 每份報告抽驗 ≥ 20 條來源；**關鍵指標附錄的 URL 100% 驗證**（開啟頁面、確認數字與年份真的在頁面上）。
- 驗證結果記錄在 `04-research-notes/verification/inbox-<檔名>-check.md`：URL｜可開啟？｜數字相符？｜年份相符？｜定義相符？｜判定。
- 失敗率門檻：
  - 無法開啟或內容不符 ≤ 10%：報告維持原等級。
  - 10–20%：報告整體降一級，且其未驗證的數字一律標【示意】。
  - > 20%：報告降為 C 級，只能作搜尋線索，不能作為任何【實際】數字的來源。

## 4. 三角驗證規則（指標層級）

| 情況 | 處理 |
|---|---|
| ≥ 3 個獨立來源（不同機構、不同方法）一致（差異 ≤ 15%） | 高信心，【實際】 |
| 2 個獨立來源一致 | 中信心，【實際】，備註「雙源」 |
| 僅 1 個來源 | 低信心，【示意】，附假設 |
| 來源互相矛盾（差異 > 30%） | 進矛盾表：先比定義、年份、方法 → 若定義不同則分桶並列；若定義相同則以 A > B > C 等級高者為準，並說明 |
| 多個 AI 引用同一來源 | 只算 1 個來源（避免「三個 AI 都抄同一篇新聞稿」被誤判為三角驗證） |
| 市調公司數字相同但機構不同 | 視為互相抄襲，只算 1 個來源 |

**禁止**：取平均、取中位數掩蓋矛盾；把預測當現況；把亞太數字拆成各國。

## 5. 整合進 V2 的順序

1. 先整合**台灣基準線**（最重要，也最常缺官方數字）：合併 V1、外部報告、璞石內部數據（CONFIDENTIAL，只用於校準，不外流）。
2. 再整合**12 市場比較表**：逐格比對 V1 與外部報告，更新為查核後數值，附來源編號。
3. 再整合各市場章節：新增 V1 沒有的事實、修正錯誤、補資料缺口。
4. 再整合跨國主題與策略意涵。
5. 產出 `05-report/asia-interior-design-market-report-v2.md` 與 `05-report/v1-to-v2-changelog.md`（每項變更：章節｜原值｜新值｜來源｜理由）。

## 7. 幻覺與偏誤檢查清單（每份外部報告）

- [ ] 有沒有「太整齊」的數字（如 CAGR 恰好 10.0%）且無來源？
- [ ] 有沒有把亞太總數當作某國數字？
- [ ] 有沒有把協會認證寫成法定證照？
- [ ] 有沒有引用 2019–2021 的數字當 2025 現況？
- [ ] 幣別換算是否錯位（日圓／韓元／越南盾常見千倍錯誤）？
- [ ] 來源 URL 是否存在、內容是否對得上？
- [ ] 是否只用英文來源而缺在地語言？
- [ ] 是否把預測（2030）寫成現況（2025）？

## 8. 需要 Banson 提供的內部數據（用於校準台灣基準線；CONFIDENTIAL）

| 項目 | 用途 |
|---|---|
| 璞石近 3 年住宅裝修案件數、平均每坪單價、平均每案金額、工期 | 校準台灣單價分級與每案均價 |

| 家居零售線：品類、坪效、與裝修線的交叉銷售比 | 校準零售整合模式 |

## 10. V1 的特殊狀況：未開頁核對

V1 產出時的執行環境只允許搜尋、不允許開啟網頁，所有數字來自搜尋摘要與多源交叉比對。因此在 V2 整合時：

1. 外部 AI 報告中「實際開啟過原文」的來源，其驗證權重高於 V1 的同一來源。
2. V1 各章來源清單的 URL 由外部 AI（或能開網頁的 Claude 會話）逐條開啟核對；核對通過才可由【示意】升級為【實際】或維持【實際】。
3. 若 Banson 的 Claude Code 環境可調整網路政策（允許全部網域或加入白名單），下一次 Claude 會話即可自行開頁核對，不必依賴外部 AI。
