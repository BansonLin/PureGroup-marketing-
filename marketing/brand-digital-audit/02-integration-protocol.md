# 整合協議（Integration Protocol）v1 — 品牌數位資產盤點

本專案沿用 `research/asia-interior-design-market/02-integration-protocol.md` 的回收、分級、驗證、裁決流程。本檔只列**差異與補充**；未提及者依該協議。

## 1. 回收（Intake）

| 步驟 | 動作 | 負責 |
|---|---|---|
| 1 | 外部報告存入 `03-inbox/<ai>/`；內部匯出存入 `03-inbox/internal/`（CONFIDENTIAL） | Banson、BU 負責人 |
| 2 | Claude 建立 `03-inbox/_intake-log.md`：檔名、AI 或系統、範圍、執行日、字數、URL 數、CSV 列數 | Claude |
| 3 | 格式檢查：8 章骨架、第 2 章比較表無空格、附錄 CSV 欄位齊；缺項記錄但不退件 | Claude |

## 2. 來源分級（本專案版）

| 等級 | 定義 | 整合用法 |
|---|---|---|
| A | 內部系統匯出（GA4、GSC、Meta 洞察、廣告管理員、電商後台、POS、CRM） | 【實際】，附匯出日；只進內部版 |
| B | 平台頁面直讀的公開數字（追蹤數、評論數、觀看數、索引頁數、PageSpeed），附 URL 與擷取日 | 【實際｜快照 YYYY-MM-DD】 |
| C | 第三方估計工具（Similarweb、Semrush、社群分析站）、AI 的「估計」 | 只作區間，標【示意】 |
| D | 無 URL 的數字、無法開啟的 URL、需登入而 AI 自稱看到的數字 | 不採用 |

## 3. URL 逐條驗證

- 每份報告抽驗 ≥ 20 條；**附錄 CSV 的 URL 100% 驗證**（本會話網路放寬後由 Claude 開頁；未放寬則由另一個 AI 交叉開頁）。
- 驗證重點：URL 可開、數字在頁面上、擷取日合理（不得晚於報告執行日）。
- 失敗率門檻與降級規則同原協議 §3。

## 4. 三角驗證（快照型指標的特別規則）

| 情況 | 處理 |
|---|---|
| 同一指標、不同 AI、擷取日差 ≤ 7 天、數值差 ≤ 5% | 一致；採最晚日期值，標【實際｜快照】 |
| 數值差 5% 到 20% | 檢查是否不同帳號（如 Wayhome 品牌層 vs 宜蘭店層）或不同口徑（追蹤 vs 粉絲）；口徑相同則採有截圖或 URL 較完整者 |
| 數值差 > 20% | 進矛盾表；由 Claude 開頁重取為準 |
| 內部匯出（A）與外部直讀（B）衝突 | 以 A 為準；B 作為外部可見性參照 |
| 關鍵字排名不同 | 排名因地區、個人化而異；三方各記，取「出現在前 10 的次數」作為指標，不取平均名次 |

## 5. 整合進盤點報告的順序

1. 先整合**單一事實表**（`04-research-notes/fact-table.csv`）：合併三份外部 CSV 與內部匯出，欄位同附錄規格，加 `source_ai` 與 `verified` 兩欄。
2. 再填**五品牌比較表**與**各品牌 8 模組**。
3. 再整合**競品數字列**（凍結名單）。
4. 再做**關鍵字排名矩陣**。
5. 產出 `05-report/01-digital-asset-audit-v1.md` 與 `05-report/00-quick-fixes.md`。

## 6. 矛盾裁決紀錄

集中在 `04-research-notes/adjudication-log.md`，欄位：編號｜品牌｜指標｜來源 1（值、日期、等級）｜來源 2｜差異原因｜裁決｜理由｜信心。

## 7. 幻覺與偏誤檢查清單（每份外部報告）

- [ ] 有沒有「太整齊」的數字（追蹤數恰好 1,000）且無 URL？
- [ ] 有沒有把 Wayhome 品牌主帳號的數字當成宜蘭店？
- [ ] 有沒有把「粉絲」與「追蹤」混用（FB 兩者不同）？
- [ ] 擷取日是否晚於報告執行日？
- [ ] 需登入的數字（IG 互動）是否被寫成直讀？
- [ ] 競品是否包含相乘創研（應排除）？
- [ ] 關鍵字排名是否標了搜尋日與地區？
- [ ] 是否夾帶行銷建議（應剔除，留到第 4 步）？

## 8. 對內／對外版

- 盤點報告與比對報告預設**對內**：含內部數據、競品負面資訊、價格比較。
- 若需對外版（例如給外包代理商）：剔除內部數據、競品負面資訊、人事資訊、工具品牌名；由 Claude 另出 `-external` 版本。
